# Команда `install` — проверка и настройка окружения

Runbook установочного режима скилла. Ты читаешь этот файл, потому что скилл вызван как
`/team-swarm install` (или `setup` / `doctor` / «проверь окружение» / «настрой team-swarm»).
Это не работа над задачей: команду не собираем, тиммейтов не спавним.

Принцип: проверяешь сам, а всё, что меняет окружение, делаешь после согласия пользователя.
**Ничего не устанавливай и не правь конфиги без явного согласия пользователя** — это его
окружение, и молчаливую правку откатывать придётся ему.

## Шаг 1. Доктор (проверка того, что лежит на диске)

```
node "<каталог скилла>/scripts/doctor.mjs"
```

`<каталог скилла>` — та же папка, где лежит этот файл; если скилл приехал плагином,
это `${CLAUDE_PLUGIN_ROOT}`. Не знаешь пути — найди: `ls -d ~/.claude*/skills/team-swarm`.

Доктор печатает по строке на проверку: `STATUS  name  detail`. Статусы:

| STATUS | Значит |
| :-- | :-- |
| `OK` | в порядке |
| `WARN` | работает, но с оговоркой — причина в строке |
| `MISS` | не установлено |
| `OFF` | выключено настройкой |
| `UNKNOWN` | проверить не удалось (например, `claude` не в PATH) |

`fix:` в строке — либо готовая команда, либо ссылка на раздел этого файла.

Что он смотрит:
- `claude` — версия Claude Code. Минимум — 2.1.295: до неё первый `SendMessage` тиммейта
  падал, пока тот не загрузит инструмент через `ToolSearch`. Ниже — `WARN`.
- `agent-teams` — флаг `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS` в окружении процесса или в `env`
  файла `settings.json` конфиг-директории (`$CLAUDE_CONFIG_DIR`, иначе `~/.claude`).
- `workflow` — не выключен ли Workflow: `disableWorkflows` в settings или
  `CLAUDE_CODE_DISABLE_WORKFLOWS`.
- `node`, рекомендованные плагины (`compound-engineering`, `impeccable`), опциональный фолбек `superpowers`, как
  загружен сам team-swarm и включён ли хук.

## Шаг 2. Живой Preflight (проверка того, чего на диске нет)

Доктор видит флаги и выключатели в файлах, но не то, что реально оказалось в списке
инструментов сессии: есть ли у `Agent` параметр `name`, интерактивна ли сессия (`echo $CLAUDE_CODE_ENTRYPOINT`), доступны ли `SendMessage` и `Workflow`.
Это видно только тебе. Выполни Preflight-гейт из
`SKILL.md → «Требования среды и Preflight-гейт»` (включая `ToolSearch("select:SendMessage,TaskStop")`)
и выдай Preflight-строку. В install-режиме она нужна так же, как в рабочем: это половина ответа
на вопрос «всё ли есть».

## Шаг 3. Отчёт

Одним сообщением: Preflight-строка + таблица доктора. Каждый не-`OK` — с одной строкой
«что это меняет» и предлагаемым фиксом. Если `hook:nudge` — `OFF`, добавь в отчёт предложение
хука из шага 5. В конце — один вопрос: какие из фиксов применить (включая хук и его режим).
Один общий вопрос, а не по вопросу на пункт: каждый вопрос заканчивает ход.

## Шаг 4. Фиксы (после согласия)

**Плагины (`MISS`).** Выполни через Bash `fix:`-команды тех плагинов, на которые пользователь
согласился. `compound-engineering` и `impeccable` предлагай по характеру задач пользователя (второй нужен
только на фронтенде). `superpowers` не предлагай: это фолбек, TDD держат изоляция, гард и гейт лида,
и доктор не считает его отсутствие проблемой; ставь, только если пользователь сам попросил. Отказ — не проблема, скилл работает и без них. После установки плагинов нужен
перезапуск сессии — скажи об этом.

**Версия (`WARN claude`).** `claude update`, затем перезапуск сессии. На старой версии скилл
запускается, но тиммейты спотыкаются на первом `SendMessage`, а ниже 2.1.288 ревьюер из
`compound-engineering`, заспавненный по имени, ещё и теряет свой промпт и инструменты.

**Agent teams (`OFF agent-teams`).** Без флага у `Agent` нет параметра `name`: каждый спавн —
обычный субагент, режим A (TDD) невозможен, режим B через Workflow остаётся. Включение —
ключ в `env` файла `$CLAUDE_CONFIG_DIR/settings.json` (или `~/.claude/settings.json`):

```json
{ "env": { "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "1" } }
```

Правь точечно, как описано в шаге 5. Флаг подхватывается после перезапуска сессии. Команды
работают только в интерактивной сессии: в `-p` и в Agent SDK тиммейтов не будет даже с флагом.

**Workflow (`OFF workflow`).** Режим B пойдёт на agent-teams — это рабочий фолбек. Если
пользователь хочет Workflow-бэкенд, убери `disableWorkflows` / `CLAUDE_CODE_DISABLE_WORKFLOWS`
(выключатель мог стоять намеренно — поэтому только с согласием). `OK` значит лишь, что этих
двух выключателей нет в окружении процесса и в settings конфиг-директории; есть ли `Workflow`
в сессии на самом деле, показывает Preflight.

**Preflight провален** (у `Agent` нет параметра `name`, сессия `sdk-*` (`-p` / Agent SDK) или нет `SendMessage`, и при этом нет `Workflow`) — чинить нечем:
объясни, что команда в этой среде невозможна, и назови причины из таблицы SKILL.md (версия
Claude Code, флаг `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS`, запуск в `-p` / SDK). Провал
Preflight — главный вывод проверки, его не сглаживают.

**Строка `skill:team-swarm`** — как загружен скилл:

- `team-swarm@skills-dir` — папка (клон или симлинк) в `~/.claude/skills/team-swarm`
  (или `$CLAUDE_CONFIG_DIR/skills/team-swarm`) с манифестом `.claude-plugin/plugin.json`.
  Полноправный способ установки: грузятся и скилл, и хук; имя скилла — `team-swarm`.
- `team-swarm@team-swarm` — установка из маркетплейса. Имя скилла с префиксом плагина:
  `team-swarm:team-swarm` (и команда — `/team-swarm:team-swarm`).
- `WARN several copies` — стоят обе. Установленный из маркетплейса плагин имеет приоритет:
  skills-dir-плагин получает «Not loaded» и его хуки выключены, но его `SKILL.md` всё равно
  грузится как plain-скилл `team-swarm` рядом с маркетплейсным `team-swarm:team-swarm` — две
  копии скилла, возможно разных версий. Предложи оставить одну:
  `claude plugin uninstall team-swarm@team-swarm` или убрать папку/симлинк из skills.
- `plain skill` — в папке нет манифеста плагина, поэтому хуки не поедут: ни напоминалка, ни гард
  изоляции (тогда изоляция tester/developer держится только на брифах). Положи папку целиком
  (клоном или симлинком), вместе с `.claude-plugin/`.

## Шаг 5. Хук-напоминалка (предложи в отчёте шага 3)

В отчёте коротко объясни, что делает хук, — ответ придёт вместе с остальными фиксами:

> На промптах, похожих на работу с кодом, хук подкладывает Claude напоминание зайти в
> team-swarm. Решение «команда или соло» и выбор режима хук не принимает — это работа
> скилла. Молчит на вопросах («почему…», «что такое…»), на слэш-командах, на явном «соло /
> без команды», на сообщениях агентов и уведомлениях задач, и после того, как скилл в этой
> сессии уже вызывался.

Режимы: `smart` (рекомендуемый), `always` (в каждый промпт пользователя), `off`.

Включение — по тому, как установлен team-swarm (строка `skill:team-swarm`). Значение опции
`nudge` приходит в хук как `CLAUDE_PLUGIN_OPTION_NUDGE`:

- Из маркетплейса — сразу при установке:
  `claude plugin install team-swarm --marketplace jokius/team-swarm --config nudge=smart`,
  или для уже установленного:
  `printf '{"nudge":"smart"}' | claude plugin configure team-swarm@team-swarm --values-stdin`
  (или `/plugin` → configure).
- Skills-dir — тем же `configure`:
  `printf '{"nudge":"smart"}' | claude plugin configure team-swarm@skills-dir --values-stdin`.
  `claude plugin configure team-swarm@skills-dir` без флага показывает опции и какие из них не заданы.
- При любой установке — переменная окружения в `~/.claude/settings.json`
  (или `$CLAUDE_CONFIG_DIR/settings.json`):

  ```json
  { "env": { "TEAM_SWARM_NUDGE": "smart" } }
  ```

  Правь точечно: прочитай файл, добавь один ключ в существующий `env`, запиши обратно.
  Чужие настройки не перезаписывай и файл целиком не переформатируй.

Env имеет приоритет над опцией плагина. Выключение — `off` или удаление ключа. Хук
подхватывается после перезапуска сессии — предупреди. Доктор читает опцию из `pluginConfigs`
в settings; если после `configure` он всё ещё пишет `OFF`, источник истины —
`claude plugin configure <плагин>`.

Проверить сам хук (включая запуск через симлинк): `node "<каталог скилла>/hooks/swarm-nudge.test.mjs"`.

Гард изоляции (`hooks/isolation-guard.*`) настраивать не нужно: он включён всегда, когда
team-swarm загружен плагином, и действует только на тиммейтов `tester-*` / `developer-*` /
`worker-*` (SKILL.md → «Изоляция»). Проверка: `node "<каталог скилла>/hooks/isolation-guard.test.mjs"`.

## Шаг 6. Итог

Одна строка вида:

> Готово: Preflight ✅ · Claude Code 2.1.296 · плагины 3/3 · хук smart (после рестарта сессии).

И, если что-то осталось незакрытым, — чего именно не хватает и что это меняет.

## Чего в install-режиме не делать

- Спавнить тиммейтов, писать спеки, начинать работу над задачей пользователя.
- Ставить плагины или править `settings.json` без согласия.
- Чинить «на всякий случай» то, что доктор показал как `OK`.
