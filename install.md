# Команда `install` — проверка и настройка окружения

Runbook установочного режима скилла. Ты читаешь этот файл, потому что скилл вызван как
`/team-swarm install` (или `setup` / `doctor` / «проверь окружение» / «настрой team-swarm»).
Это **не** работа над задачей: команду не собираем, teammates не спавним.

Принцип: **чинить сам то, что чинится безопасно и обратимо, остальное — с апрувом пользователя.**
Ничего не устанавливать и не править конфиги молча.

## Шаг 1. Доктор (проверка того, что лежит на диске)

```
node "<каталог скилла>/scripts/doctor.mjs"
```

`<каталог скилла>` — та же папка, где лежит этот файл; если скилл приехал плагином,
это `${CLAUDE_PLUGIN_ROOT}`. Не знаешь пути — найди: `ls -d ~/.claude*/skills/team-swarm`.

Доктор печатает по строке на проверку: `STATUS  name  detail`, где STATUS —
`OK` / `MISS` / `OFF` / `UNKNOWN`. Строки с `fix:` содержат готовую команду.
Он смотрит: сам Claude Code, node, рекомендованные плагины (`superpowers`,
`compound-engineering`, `impeccable`), как загружен сам team-swarm и включён ли хук.

## Шаг 2. Живой Preflight (проверка того, чего на диске нет)

Доктор **не** проверяет `Agent` / `SendMessage` / `Workflow` — они живут в списке
инструментов сессии, а не в файлах, и видны только тебе. Выполни обычный Preflight-гейт из
`SKILL.md → «Требования среды и Preflight-гейт»` (включая `ToolSearch("select:SendMessage")`)
и выдай Preflight-строку. В install-режиме она обязательна ровно так же — это половина ответа
на вопрос «всё ли есть».

## Шаг 3. Отчёт

Одним сообщением: Preflight-строка + таблица доктора. Каждый не-`OK` — с одной строкой
«что это даёт» и предлагаемым фиксом. Без простыней: пользователь должен видеть, что сломано
и что ты предлагаешь сделать.

## Шаг 4. Фиксы (с апрувом)

**Плагины.** Для каждого `MISS` спроси, ставить ли, и по согласию выполни `fix:`-команду из
вывода доктора через Bash. `superpowers` рекомендуй активно (без него teammates работают без
enforced TDD/debug-методологий), `compound-engineering` и `impeccable` — по характеру задач
пользователя (второй нужен только на фронтенде). Отказ — не проблема, скилл работает и без них.

После установки плагинов **нужен перезапуск сессии** — скажи об этом явно.

**Preflight провален** (нет `Agent`, или нет ни `SendMessage`, ни `Workflow`) — чинить нечем:
объясни, что команда в этой среде невозможна, и назови причины из таблицы SKILL.md (версия
Claude Code, флаг `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS`). Не изображай, что всё в порядке.

**`skill:team-swarm` = «plain skill»** — папка скилла без манифеста плагина, хук в такой
конфигурации не поедет. Это нормально, если хук не нужен; иначе скажи, что нужна установка
плагином (см. README) или манифест `.claude-plugin/plugin.json` в папке скилла.

## Шаг 5. Хук-напоминалка (спроси, нужна ли)

Спроси пользователя, включать ли хук, коротко объяснив, что он делает:

> На промптах, похожих на работу с кодом, хук подкладывает Claude напоминание зайти в
> team-swarm. Решение «команда или соло» и выбор режима хук **не** принимает — это работа
> скилла. Молчит на вопросах («почему…», «что такое…»), на слэш-командах, на явном «соло /
> без команды» и после того, как скилл в этой сессии уже вызывался.

Режимы: `smart` (рекомендуемый), `always` (в каждый промпт), `off`.

**Включение — по тому, как установлен team-swarm** (видно в строке `skill:team-swarm`):

- Плагином из маркетплейса → нативный userConfig:
  `claude plugin install team-swarm@team-swarm --config nudge=smart`
  (или `/plugin` → configure). Значение приедет в хук как `CLAUDE_PLUGIN_OPTION_NUDGE`.
- Локально (skills-dir) или просто «хочу надёжно» → переменная окружения в
  `~/.claude/settings.json` (или `$CLAUDE_CONFIG_DIR/settings.json`):

  ```json
  { "env": { "TEAM_SWARM_NUDGE": "smart" } }
  ```

  Правь **точечно**: прочитай файл, добавь один ключ в существующий `env`, запиши обратно.
  Не перезаписывай чужие настройки и не переформатируй файл целиком.

Env имеет приоритет над userConfig. Выключение — `off` или удаление ключа.
**Хук подхватывается только после перезапуска сессии** — предупреди.

## Шаг 6. Итог

Одна строка вида:

> Готово: Preflight ✅ · плагины 3/3 · хук smart (после рестарта сессии).

И, если что-то осталось незакрытым, — чего именно не хватает и что это меняет.

## Чего в install-режиме делать НЕ надо

- Спавнить teammates, писать спеки, начинать работу над задачей пользователя.
- Ставить плагины или править `settings.json` без явного согласия.
- Чинить «на всякий случай» то, что доктор показал как `OK`.
- Молча пропускать провал Preflight — это главный вывод проверки, а не деталь.
